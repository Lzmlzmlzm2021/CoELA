## 相对原始 CoELA 的最终改动

| 方面 | CoELA 基线 | V4 sharing bed |
| --- | --- | --- |
| 高层决策 | 两个本地 LLM 分别根据自身观察、记忆和对话选计划 | 仍由两个本地 LLM 选计划，额外读取各自的 V4 决策卡 |
| 协作记忆 | 主要依赖各 agent 的本地记忆和自然语言通信 | 共享板维护目标账本、实体身份、持有关系、持续任务、claim、预约、执行证据与协作事件 |
| 动作冲突 | 两个 agent 的提案通常直接送环境 | 协调器先原子核对重复 claim、物理持有、已交付、房间预约与循环保护，再送环境 |
| 床位 | 每个 agent 依赖自己感知到的床位位置 | 一方观察到的有效床位可通过 `delivery_target` 给另一方使用；本地直接感知优先，跨 episode 数据拒绝 |
| 交付记账 | 本地执行结果可能先影响 `satisfied` | V4 以 evaluator 确认的得分物体为准；放下但未计分会产生失败证据和待恢复任务 |
| 通信 | 可交换模型生成的自然语言消息 | V4 消息绑定公开的结构化协作事件 ID，发送受限字段，避免把私有观察当作共享事实 |
| 底层技能 | `AgentMemory` 与原始导航、探索、抓取、装箱和运输执行器 | 原样沿用这些技能；V4 只适配共享床位输入并协调高层动作 |

V4 的中心组件维护事实和资源一致性，策略选择仍由各 agent 的 LLM 自主完成。共享床位只在共享板掌握有效三维坐标后出现，不推断未知床位。

## 验证范围

在 `tdw_mat` 执行 `python -m unittest discover -s tests -q`，全部单元测试通过。测试覆盖 V4 机制及基线入口关键路径；没有在本次整理中运行 24 个 TDW 场景，因此本报告不宣称性能分数或完整基准复现。Git 历史保留旧版代码，可通过历史提交和分支恢复。
